# 模型术语图鉴 · Model Glossary

把 AI 模型里最常被提起、也最容易被含糊带过的那批词讲清楚：**词元、上下文、上下文占用、成本、
缓存命中、蒸馏、破甲、智能体、插件、API、多模态、会话、思考等级、权限、工作空间、开源协议，
以及 GPQA、HLE 这些基准**——一共九组、88 条。

左边是正文，右边是目录。**点目录里的任一条，正文滚到它并点亮；滚动正文时目录会自己跟着亮。**
每条都写了「它为什么存在」和「什么时候会咬你一口」，有争议的地方会写明按谁的口径。

## 为什么是这个顺序

顺序本身就是要说明的事：先讲清楚「一句话值多少钱」（**计量与计费**），
再讲这句话经历了什么（**一次请求里发生的事**），然后是那个东西到底是什么（**模型本身**），
接着才是它想不想得明白（**思考与推理**）、有多强（**能力与评测**）、能不能替你把事办成
（**让模型干活**）、边界在哪（**安全与边界**）、文字之外的部分（**多模态与生成**），
最后落到买与用的现实（**生态**）。

从头往下读，是一条从「词元」走到「上线之后怎么发现它变差了」的线；跳着看也成立，
每条都自带一篇尽量能独立读懂的解释。

## 内容上守的两条

1. 每个词都给「它为什么存在」和「什么时候会咬你一口」，不给背诵式的定义。
2. 凡是会变或有争议的口径（价格、榜单名次、协议条款、缓存折扣），都写明「按谁的算法」
   「什么时候会变」，而不是给一个看起来很确定的数字。

涉及攻击手法的条目（**破甲**、**提示注入**）只讲它是什么、危险在哪、该怎么防，
不给可操作的做法。

## 加一条术语

在对应分组的文件里 `T.push(...)` 一个对象就行：

```js
{
  id: 'term-id',            // 英文短横线，用于 #term-<id> 深链与互链
  term: '中文名',
  en: 'english name',       // 可省
  group: 'usage',           // terms-groups.js 里的分组 id
  lead: '一句话定义，会被加粗显示。',
  body: [
    '一段正文。支持 **加粗** 这一种行内记号。',
    { bullets: ['要点一', '要点二'] },
    { head: ['列一', '列二'], rows: [['a', 'b']] }   // 会渲染成表格
  ],
  pitfall: '常见的坑（可省，会单独框出来）。',
  related: ['context-window', 'cost']   // 必须是别的条目 id，点了会跳过去
}
```

写完用 Node 跑一遍自检，能挡住重复 id、写错分组、互链指向不存在的条目这三类错：

```bash
node -e "global.window=global;require('./data/terms-groups.js');
for(const f of ['01-usage','02-request','03-model','04-thinking','05-bench','06-agentic','07-safety','08-media','09-eco'])require('./data/terms-'+f+'.js');
const G=window.GLOSSARY_GROUPS,T=window.GLOSSARY_TERMS,ids=new Set();
T.forEach(t=>{ids.add(t.id);(t.related||[]).forEach(r=>{if(!ids.has(r)&&!T.some(x=>x.id===r))console.log('坏链',t.id,'->',r)})});
console.log(T.length+' 条 / '+G.length+' 组');"
```

## 与另两个页面的关系

同一仓库里还有两份：`../model-atlas`（模型能力图鉴：能力 - 成本散点图 + 排行榜）和
`../last-token`（最后的 Token：一张 AI 模型拟人化的「最后的晚餐」）。

仓库里三个目录是平级的，站点上则是「最后的 Token 在站点根、另两个是它的子目录」，
所以页面之间的相对地址按「是不是挂在公网服务器上」分两套——`app.js` 里的 `LOCAL` 那个常量
就是这件事，改的时候两边都要照顾到。

`styles.css` 与 `ambience.js` 是从 `../model-atlas` 抄过来的，设计令牌与氛围层保持一模一样；
本目录的 `styles.css` 在末尾多了一节术语卡与目录的样式。改这两个文件时不用同步回去，
但改设计令牌（颜色、圆角、字体）时应该三个页面一起改，否则风格会分家。
